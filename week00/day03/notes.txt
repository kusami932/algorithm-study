		if (!st.empty()) => int value = st.top => st.pop
	
Python에선 별도의 스택 클래스를 만들 필요가 없음
	• list의 오른쪽 끝을 스택의 top으로 사용
	• C++과 달리 pop에서 제거된 값을 반환함 (value = stack.pop)
	• 빈 리스트에서 stack[-1] or stack.pop을 실행하면 IndexError 발생
		조건 검사: if stack || if len(stack) > 0

1) 함수의 의미 / 계약 - 함수가 무엇을 반환하는지 한 문장으로 정의
	** factorial(n)은 음이 아닌 정수 n에 대해 n!을 반환한다

2) Base Case - 더 이상 재귀 호출 없이 직접 답을 반환하는 가장 작은 문제
	** 0! = 1 => if (n == 0) return 1
	• 없으면 재귀 호출이 끝나지 않음 (계속 호출하다가 호출 스택의 공간을 모두 사용)

3) Recursive Case & Progress
	-- 문제를 더 작은 같은 형태의 문제로 줄이는 부분
	** 재귀 호출의 입력이 base case에 가까워져야 한다는 것
		종료되는 재귀 함수
			1. 도달 가능한 base case
			2. 모든 재귀 호출이 입력을 base case에 더 가깝게 만듬

Call Stack
	프로그램이 함수를 호출하면 실행 중인 함수에 관한 정보가
	호출 스택에 저장됨 => 스택/호출 프레임 (이러한 정보들의 묶음)
		• 함수의 매개변수
		• 지역 변수
		• 함수 실행이 끝난 후 돌아갈 위치
		• 함수 실행을 이어가기 위해 필요한 상태

Stack vs Call Stack
	Stack 자료구조: 프로그래머가 데이터를 LIFO 순서로 관리하기 위해 사용하는 자료구조
	Call Stack: 프로그램이 함수 호출과 복귀를 관리하기 위해 사용하는 실행 메모리 구조
		재귀 함수는 호출될 때마다 새로운 호출 프레임을 호출 스택에 추가 (내부적 사용)
		
Factorial(4)의 호출 과정
	top
		factorial(0) = 1
		factorial(1) = 1 × 1 = 1
		factorial(2) = 2 × 1 = 2
		factorial(3) = 3 × 2 = 6
		factorial(4) = 4 × 6 = 24
	bottom
		• 가장 마지막에 호출된 factorial(0)이 가장 먼저 끝남
		• factorial(0)이 1을 반환하면 호출들이 역순으로 완료됨 (0 -> 1 -> 2 -> 3 -> 4)
	
factoral의 수학적 정의
	1 if n = 0 ==> 0! = 1 (Base Case)
	n x (n - 1)! if n > 0 ==> n! = n * (n - 1)! (Recusive Case)
	
int overflow 주의
	C++의 long long은 저장할 수 있는 값의 크기가 제한
		• 20!은 signed 64-bit long long에 들어감 (21!부터 범위 초과)
	
복잡도
	factorial(n) => n + 1만큼 다음 함수를 차례로 호출
		총 호출 횟수 n + 1 / 시간 복잡도: O(n)
		호출 스택 공간 복잡도: O(n)
	
재귀 fibonacci가 느린 이유
	fib (3), fib(2)가 여러 번 계산된다
	fib (1)과 fib(0)은 훨씬 더 많이 호출된다
		=> 한 번 계산한 결과를 기억하지 않기 때문
	
	재귀 호출 횟수에 대한 점화식: T(n) = T(n - 1) + T(n - 2) + O(1)
	실행 시간이 피보나치 수열과 비슷한 속도로 증가 약  O(2^n)
	
	공간 복잡도는 호출 트리 전의 노드 수가 아니라 한순간에 가장 깊게 쌓이는 호출 경로 기준
		=> 최대 재귀 깊이는 n에 비례함

반복문으로 피보나치 구현하기
	previous = F (n - 2)
	current = F (n - 1)
	next = previous + current
	
단순 재귀: O(2^n) / O(n) => 정의와 유사하지만 중복 계산이 많음
반복문: O(n) / O(1) => 빠르고 메모리 효율적
메모이제이션 재귀: O(n) / O(n) => 계산 결과를 저장해 중복 제거
DP 배열: O(n) / O(n) => 이전 결과를 배열에 저장
