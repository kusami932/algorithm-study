** 이 문제에서는 어떤 정보를 저장해야 하며, 
	그 정보를 얼마나 빠르게 찾을 수 있어야 하는가?"

	• 숫자를 입력받은 순서대로 저장
	• 각 숫자가 몇 번 등장했는지 알아야 함
	• 특정 숫자가 이전에 등장했는지 확인해야 함
	• 문자열에서 가장 자주 등장한 문자를 찾아야 함

배열 -> 데이터를 순서대로 저장 / 인덱스로 원소 접근
문자열 -> 문자들을 순서대로 확인
해시맵 -> 값별 등장 횟수 기록 / 중복된 값 찾기 / 값과 다른 정보를 연결
집합 -> 값의 존재 여부만 기록 / 중복된 값 찾기

	1. 배열과 해시맵의 역할은 어떻게 다른가?
	2. 중복을 찾을 때 왜 이중 반복문보다 집합이 유리한가?
	3. 빈도수 세기란 무엇인가?
	4. 한 번의 순회와 두 번의 순회는 어떻게 다른가?
	5. O(n), O(n log n), O(n^2) 풀이를 어떻게 구분하는가?

문제풀이 관점에서의 자료구조:
	앞으로 수행할 연산을 효율적으로 처리하기 위해 데이터를 배치하는 방법

		배열에 저장 => 입력된 순서, 각 원소의 위치, 전체 원소 목록, 중복된 원소 등의 정보 보존
		빈도수 해시맵에 저장 => 어떤 값이 등장했는가? 각 값은 몇 번 등장했는가?
	ㄴ> 같은 데이터를 저장하더라도 앞으로 어떤 질문에 답하는지에 따라 적합한 구조가 달라짐

	ㄴ> 잘못 처리하면 C++에서는 잘못된 메모리 접근이 발생 / IndexError 발생

	2. 범위 기반 순회
		for (int x : arr) - 모든 값을 확인할 때는 이쪽이 더 쉬움

해시맵: 값으로 정보를 빠르게 찾는 구조
Key-Value 관계
	학생 이름과 점수 연결 (Alice -- 90 / Bob -- 85 / Chris -- 93)
	
• 위치(인덱스)를 사용해 값을 찾는다 < ---- > key를 사용해서 값을 찾는다
	몇 번째 위치에 있는 값인가 vs 이 key와 연결된 값은 무엇인가

unordered_map<string, int> score
	값 저장: score["key_name"] = num_value;
	값 조회: score["key_name"]
	값 수정: score["key_name"] = new_value;
	존재 여부 확인: 
		score.find("key_name") != score.end()
		score.count("key_name") > 0
	unordered_map의 원소 순회
		for (const auto& [name, value] : score)

	unordered_map에서 존재하지 않는 key에 [] 연산자를 사용하면 기본값이 만들어짐
	unordered_map<int, int> freq; => 처음에는 비어 있음
	freq[10]++;
		내부적으로 처리되는 과정
			1. key 10이 있는지 찾는다
			2. 없다면 freq[10] = 0을 만든다
			3. 값을 1 증가시킨다
			4. 결과적으로 freq[10] == 1이 된다
		=> 빈도수 세기에서 자주 사용하는 패턴: for (int x : arr) freq[x]++;
		
Python dict: score = {}
	값 저장/조회/수정/존재 여부 확인/순회
	기본값 사용 시 score.get("key", 0)
	빈도수 세기
		freq = {}
		for x in arr:
			freq[x] = freq.get(x, 0) + 1

시간복잡도 평균 O(1) - 삽입, 조회, 삭제, 존재 여부 확인
	** 해시 충돌이 심하게 발생하는 특수 상황 시 worst-case는 더 나빠짐

map<int, int> orderedMap VS unordered_map<int, int> hashMap
	key 순서: 정렬된 순서 유지 vs 순서 보장 없음
	검색·삽입: O(log n) vs 평균 O(1)
		빠른 검색과 빈도수 세기 => unordered_map 사용
	
	결과를 key 순서대로 출력해야 한다면 - map 사용, key들을 별도 배열에 모아 정렬, 빈도수 배열 사용

집합: 중복되지 않는 값들의 모음 (존재 여부만 저장하는 구조)
	값에 연결된 추가 정보가 필요하지 않을 때 유용
		값이 이미 등장했는가
		방문한 노드인가
		금지된 단어인가
		중복된 숫자인가
		서로 다른 값은 몇 개인가

해시맵: 값 -> 추가 정보 / 집합: 값이 존재하는가?
	frequency[10] = 3 - 10과 등장횟수 3을 연결해야 하므로 해시맵이 필요함
	10을 이전에 본 적이 있는가? -> 집합이면 충분
	
unordered_set<int> seen; 
	seen.insert(10); seen.insert(20); seen.insert(10) // [10, 20]
	존재 여부 확인
		seen.find(10) != seen.end() / seen.count(10) > 0
	삭제: seen.erase(10);
	원소 개수: seen.size()
	
Python set seen = set() -> add, remove, discard
시간 복잡도 평균 O(1) -> 중복 탐지 (반복적으로 이 값을 본 적이 있는가)를 확인할 때 배열보다 효율적


배열과 해시 자료구조를 선택하는 기준
	배열 먼저 - 원소의 순서가 중요하다, 인덱스가 필요하다, 이웃 원소 비교, 연속 구간 처리, 전체를 순차적으로 훑기
	[10, 20, 10, 30] -> 10이 두 번 들어 있다는 사실뿐만 아니라 각각의 위치도 보존됨
	
	해시맵 먼저 - 각 값에 관한 추가 정보를 저장, 값별 등장 횟수, key-value 대응관계, 특정 값 빠르게 찾기
	
	집합 먼저 - 값 존재 여부만, 이미 처리한 값인지 확인, 중복 제거, 서로 다른 값의 개수
	
빈도수 세기: 각 값이 전체 데이터에서 몇 번 등장했는지
	가장 많이 등장한 값, 중복된 값, 두 배열이 같은 원소를 얼마나 포함하는지
	애너그램 판별, 과반수 원소, 투표 집계, 문자 개수 비교, 두 수의 합, 구간 빈도 처리
	
값의 범위가 작다면 빈도수 배열도 가능 - 값이 정수일 때, 최소/최대 범위를 알때, key를 정렬된 순서로 확인

Two-pass scan / one-pass scan
	배열이나 문자열의 각 원소를 처음부터 끝까지 한 번 확인하는 것 O(n)
	전체 데이터를 두 번 흝는 구조 (첫 번째 작업, 두 번째 작업) O(n) + O(n) == O(2n) == O(n)
		중첩 반복문: 바깥 반복문 한 번마다 안쪽 반복문이 n번 실행됨 O(n^2)
		
	문자열에서 가장 많이 등장한 문자 찾기
		첫 번째 순회: 각 문자의 빈도수 세기
		두 번째 순회: 각 문자의 빈도수를 확인하여 최댓값 찾기
		
		=> 작업을 두 단계로 분리하면 코드가 명확해짐
			1. 필요한 정보를 수집한다
			2. 수집된 정보를 이용해 정답을 결정한다
	
	왜 한 번에 처리하지 않는가? -> 빈도수가 최종적으로 확정되어야 판단할 수 있는 문제의 경우
		문자열에서 정확히 한 번 등장한 첫 번째 문자 (swiss)
			-> 첫 문자를 봤을 땐 뒤에서 다시 등장할지 알 수 없음
				1. 모든 문자의 빈도수를 센다
				2. 원래 문자열 순서대로 확인하여 빈도수 1인 첫 문자를 찾는다
					=> 왼쪽에서부터 보면 w가 첫 번째 비반복 문자
